Glassine is a Swift package — SwiftUI for the chrome, AppKit for the editor — with one dependency, Sparkle, for the direct download's updates, and no Xcode project. A shell script assembles the app. The source is at [github.com/a-libre/glassine](https://github.com/a-libre/glassine) under the MIT license.

## Build

You need Xcode (free, from the App Store) for its toolchain; the Xcode app itself never has to open.

```bash
git clone https://github.com/a-libre/glassine.git
cd glassine
./build.sh --install     # compiles, copies Glassine.app to /Applications, opens it
```

| Command | |
|---|---|
| `./build.sh` | Build only, into `build/Glassine.app` |
| `./build.sh --run` | Build and open it from there, without installing |
| `./build.sh --install` | Build, copy to `/Applications` (asking a running copy to quit first), open |
| `./build.sh --debug` | A faster, unoptimised compile while you are changing things |
| `./build.sh --appstore` | The sandboxed App Store flavor, locally — without Sparkle, since the store is its updater |
| `./build.sh --demo` | *Glassine Demo.app*, for pictures and recordings — [below](#a-demonstration-copy) |

Edit anything under `Sources/` and run `./build.sh --run`; incremental builds take a few seconds. Opening `Package.swift` in Xcode and pressing Run works for debugging, but the assembled app from `build.sh` is the one to use day to day — it has the icon and a stable identity for macOS permissions.

The minimum deployment target is macOS 14. It is developed on macOS 26 and 27 with Xcode 26.

## Layout

```
Sources/
  Shared/     Everything both platforms compile — most of the app
    App/        AppState, Settings, Theme
    Library/    Library (folder scanning and file operations), Document (autosave, renaming), GitHubSync
    Editor/     MarkdownStyler, StyleConfig, MarkdownHTML, DateToken, CaretShape, TaskReorder
    UI/         ContentView, SidebarView, GalleryView, DailyTimelineView, ReviewView,
                SettingsView, ShortcutSheet, Overlays, Backdrop (the Metal shader), GlassBackdrop
    Support/    Platform (the seam between the shared code and each shell), Distribution
                (sandbox / App Store differences), DailyNotes, Shelf, small extensions
  Mac/        The AppKit shell: GlassineApp (scenes, menus, the key monitor), GlassineTextView
              (smooth caret, layout, typewriter, focus, motion) and its layout manager,
              the glass window, PDF export, ScreenshotMode, the updater
  iOS/        The UIKit shell, under way; not built by Package.swift
Resources/    Info.plist, the icon (make_icon.py draws it), entitlements per flavor, the wordmark
docs/
  appstore/   The store listing, a showcase library, and the script that takes the screenshots
  screenshots/ The pictures the README uses
  site/       This site
site/         glassine.ink, the one-page front door (static HTML on Vercel; vercel.json holds the redirects)
ios/          The iOS app, under way: project.yml (xcodegen makes the Xcode project) and build-sim.sh
tests/        synctest.sh, compare-shots.sh, ioscheck.sh
build.sh      Assembles and signs Glassine.app (--appstore for the sandboxed flavor)
release.sh    Notarized .dmg for direct download
appstore.sh   Signed .pkg for the Mac App Store
```

## Two flavors

`./build.sh --appstore` compiles with `APPSTORE` set, which turns on the App Sandbox, gives the app its own iCloud container instead of direct access to iCloud Drive, remembers chosen folders with security-scoped bookmarks, and leaves out the GitHub update check. `Support/Distribution.swift` is where the differences are decided at run time. [RELEASING.md](https://github.com/a-libre/glassine/blob/main/RELEASING.md) in the repository has the whole pipeline for both — certificates, notarization, the store package.

## A demonstration copy

`./build.sh --demo --install` makes and installs *Glassine Demo.app* beside Glassine: the same app compiled with `DEMO` set, under an identifier of its own (`com.alexlibre.glassine.demo`), so its settings, window, themes and library are its own and the real library is never in view. Its library is the showcase of the store pictures — `docs/appstore/library`, copied into the bundle — written into `~/Library/Application Support/Glassine Demo/Library` on the first launch with the daily notes dated from today, so the Timelapse and the gallery look lived-in on any day. It has no updater and is not registered as an editor of Markdown files, so Finder's Open With still lists Glassine once. The menu bar says Glassine; Finder and the Dock say Glassine Demo.

Two items in its Help menu: **Reset Demo Library** writes the pages fresh (what was there goes to the Trash), and **Window at 1440 × 900** sets the window to the store's picture size, 2880 × 1800 pixels on a Retina display. Add pages to `docs/appstore/library` to have them in the demo: a daily note is `Daily/N.md` for N days ago with `{{DATE}}` for its title, and `{{TOKEN}}` or `{{TOKEN-3}}` anywhere is today, or three days ago, written as a date token.

## Debugging

Help → Copy Debug Info (⌘⌥⇧D) snapshots the caret's geometry, the text view's frame and insets, and every setting, ready to paste into an issue.

The app can also photograph itself: launched with `-glassine.shoot name.png` and a few companion arguments (see `Support/ScreenshotMode.swift`), it opens at a fixed size with the settings, view and caret position you name, waits for layout, asks the window server for a picture of its own window — that window only, so nothing needs the Screen Recording permission — and quits. `-glassine.shootCapture 1` asks for the fuller composite with the backdrop beneath, which the store pictures use; macOS counts that as screen recording and says so with a notice. `docs/appstore/screenshots.sh` takes the store pictures this way from the sandboxed build, `site/screenshots.sh` the ones on glassine.ink, in the README and in this manual from the direct build — a selection (`-glassine.shootSelect 12,20`) brings up the formatting bar and a typed slash (`-glassine.shootSlash 1`) the slash menu — and it is how visual changes are checked without anyone sitting at the Mac.

`tests/shot-syntax.sh <case>` takes the layout checks — the editor on a temp copy of a showcase document, each case a setting, a caret position, a section of Settings, a trip through Review and back — into `dist/preview/`. The sync with GitHub has a test of the same spirit: `tests/synctest.sh` launches the built app headless (`-glassine.syncTest`) for one round at a time between two library folders and a folder standing in for the repository, and checks adds, edits, removals, renames, a conflict, a busy file and a quiet round — no network, no token.

## The front door

[glassine.ink](https://glassine.ink) is one static page in `site/`, served by Vercel from the same repository; a push to `main` publishes it too. `site/vercel.json` carries the redirects: `glassinewriter.com` and `www.` to `glassine.ink`, and short paths like `/docs`, `/privacy`, `/changelog`, `/support` and `/download` to where those live. Nothing on it changes often — everything that does lives here, in the manual.

## This site

This site, [docs.glassine.ink](https://docs.glassine.ink), lives in `docs/site` in the same repository and is built by [Mintlify](https://mintlify.com): `docs.json` is the navigation and `*.mdx` are the pages. A push to `main` publishes it within a minute or two. To preview locally:

```bash
npm i -g mint
cd docs/site
mint dev
```

`mint validate` and `mint broken-links` check a change before it goes up.

The rule for keeping it current is simple: a change that a person using Glassine would notice — a new key, a setting, a behaviour, a small delight — updates the page it belongs to and adds a line to the [changelog](/about/changelog) in the same commit.
